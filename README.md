# 微型工单系统前端

这是微型工单系统的 Vue 3 前端，对应后端项目：../mini-system-backend。

当前已接入 M6.4：登录与会话恢复、商户身份展示、工单列表、搜索筛选、分页、详情、创建、组内分配与改派、跨组转派、不可用处理人交接、评论、解决、退回及关闭。

## 访问范围

- 商户普通成员显示“我提交的工单”；商户管理员显示“本商户工单”，并可按服务端许可回复、退回或关闭本商户其他成员的工单。
- 工单创建只提交标题、描述、分类和优先级，商户与默认客服组由服务端确定。页面展示当前商户，不能自行指定其他商户。
- 普通客服显示“分配给我的工单”；至少管理一个客服组的账号显示“客服组工单”，可以查看管理组的全部工单。兼任其他组普通客服时，在其他组仍仅能查看分配给自己的工单。
- 无有效商户或客服组的账号显示“暂未配置访问范围”，不显示创建入口；管理员配置后可点击“刷新工作台”重新获取身份。
- 操作按钮使用工单响应的 `allowedActions`。客服组内分配和改派由平台管理员或当前组长执行，处理人候选按客服组查询。
- 列表、详情及其刷新先重新获取 `/auth/me`。请求失败、权限丢失或退出时清除受保护的数据；请求代次检查阻止旧请求回填缓存，列表总数与组织身份一起刷新。
- 商户默认路由不可用时提示联系管理员并保留创建表单；退回时处理人失效会提示等待交接并保留退回原因。

服务端仍是权限判断的最终依据。前端展示身份和隐藏入口不能替代商户数据隔离；本阶段应在独立测试库验证，不能仅凭前端升级开放多商户流量。

## M6.4 调度与交接

- 平台管理员和客服可按授权客服组筛选；管理员及当前筛选组的组长可进一步筛选未分配或具体处理人。未选组时不加载全平台候选人。
- 跨组转派仅平台管理员可用：待分配工单只选择目标客服组，继续保持待分配；处理中工单同时选择目标组处理人，继续保持处理中。
- 原处理人不可用时，服务端可返回 `handover` 操作。组长在当前客服组内交接，管理员可选择目标客服组；处理中、已解决工单交接后保留原状态。
- 转派和交接必须填写原因。切换目标客服组会清空处理人选择，重新查询该组有效候选人；旧查询响应和已关闭弹窗的响应会被丢弃。客服同时属于新旧两组时，可以作为跨组转派的目标处理人。
- 时间线展示 `TRANSFERRED`、`HANDED_OVER` 事件及客服组、处理人变化；并发冲突要求先刷新身份及工单后重试。
- 本阶段不提供账号停用管理页面。成员状态治理通过后端运维流程执行，前端负责已失效处理人的工单交接。

主要接口：`GET /support-groups`、`GET /users/agents?groupId=...`、`POST /tickets/{id}/transfer`、`POST /tickets/{id}/handover`。接口统一位于 `/api/v1` 下；转派/交接提交 `version`、`groupId`、`assigneeId`（待分配转派为空）和 `reason`。

## 启动

先启动后端，再启动前端：

    cd ../mini-system-backend
    mvn spring-boot:run

    cd ../mini-system-frontend
    pnpm dev

Vite 会将 /api 请求代理到 http://localhost:8080。前端不保存登录 Token，认证由后端 HttpOnly Cookie 管理。

开发账号使用后端显式初始化的 M6 商户、客服及管理员账号，初始化方法见后端 README.md。旧账号若尚未核实组织归属，将显示无访问范围；不要通过重置日常数据库绕过归属核对。

## 验证

    pnpm run build
